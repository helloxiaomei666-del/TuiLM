# 公开试用版与内部 SDK 测试版边界说明

## 1. 文档目的

本文用于明确《退了吗 / TuiLM》在当前阶段的两条产品与技术边界：

- 面向外部用户的公开试用版边界。
- 面向团队内部验证的 SDK 测试版边界。

本文重点约束产品能力、技术接入方式、SDK 使用方式、真实行情使用方式、商业授权前提和宣传口径，避免公开试用功能、内部技术验证和商业化授权被混用。

该文档是产品与技术边界文档，不代表真实 SDK 验证已经完成，也不代表项目已经取得任何商业数据授权。

## 2. 当前项目背景

《退了吗 / TuiLM》当前以退休进度、现金流退休率、被动收入覆盖率和资产记录为核心体验。项目需要同时支持两类工作：

- 公开试用：让用户在不接入真实 SDK 的情况下体验退休进度和资产记录能力。
- 内部验证：让团队在受控环境中验证 SDK 只读能力、字段映射、错误码和服务端适配方案。

当前阶段继续坚持 Mock First。公开试用版不接真实 SDK，不展示真实实时行情，不对外提供真实行情服务。

## 3. 为什么要分离公开试用版与内部测试版

公开试用版与内部 SDK 测试版必须分离，原因如下：

- 产品风险不同：公开试用版面向真实用户，任何行情、收益、建议表达都可能被理解为投资服务或收益承诺。
- 技术风险不同：SDK 验证涉及权限、调用额度、错误码、字段语义、数据协议和服务端隔离，不能直接暴露给前端、小程序或 H5。
- 授权边界不同：个人 SDK 权限、测试额度或订阅额度不等于商业授权，不能包装为对外商业服务能力。
- 合规口径不同：未完成企业授权、数据协议、费用、白名单和使用范围确认前，不能宣传已经对外接入真实行情。

因此，公开试用版只承载可公开、可解释、低风险的产品体验；内部 SDK 测试版只承载本地、只读、受控的技术验证。

## 4. 公开试用版定位

公开试用版是《退了吗 / TuiLM》的外部体验版本，用于验证用户是否理解并愿意使用退休进度、资产记录和现金流分析功能。

公开试用版的定位是：

- 退休进度展示工具。
- 手动资产记录工具。
- 现金流和被动收入覆盖率演示工具。
- Mock 行情与延迟公开数据体验环境。

公开试用版不是证券行情服务，不是投资顾问服务，不是交易系统，也不是银河 SDK 的公开接入版本。

## 5. 公开试用版允许能力

公开试用版允许提供以下能力：

- 手动输入资产。
- 现金流退休率计算。
- 被动收入覆盖率。
- 资产记录。
- Mock 行情。
- 延迟公开数据。
- 用户自填收益。
- 退休进度展示。

这些能力必须围绕用户自填数据、模拟数据、延迟公开数据和退休进度表达展开，不得暗示系统正在使用银河真实实时行情。

## 6. 公开试用版禁止事项

公开试用版禁止以下事项：

- 直接调用银河 SDK。
- 使用个人 SDK 权限对外提供真实行情。
- 展示银河真实实时行情。
- 做真实行情订阅。
- 做自动交易。
- 输出投资建议。
- 输出买卖建议。
- 承诺收益。
- 宣传“已接入银河真实行情”。

公开试用版中的任何行情相关内容，都必须明确为 Mock 行情、演示数据、用户自填数据或延迟公开数据，不得让用户误认为项目已经具备真实实时行情商业服务能力。

## 7. 内部 SDK 测试版定位

内部 SDK 测试版是团队内部使用的技术验证环境，用于验证 SDK 的最小只读能力和服务端适配路径。

内部 SDK 测试版的定位是：

- 本地 SDK 能力验证环境。
- quote-service / yinhe adapter 实验环境。
- Mock Provider 与真实 Provider 字段对齐环境。
- 错误码、字段映射和最小接口语义整理环境。

内部 SDK 测试版不是公开试用产品，不面向真实用户开放，也不作为商业授权证明。

## 8. 内部 SDK 测试版允许能力

内部 SDK 测试版允许进行以下工作：

- 本地 SDK 能力验证。
- quote-service adapter 实验。
- Mock Provider 与真实 Provider 对齐。
- 字段映射。
- 错误码整理。
- 最小只读接口验证。

内部验证应以最小范围、最少接口、只读能力为原则。验证重点是确认数据结构、调用方式、错误处理和服务端隔离方案，而不是扩大数据抓取或订阅规模。

## 9. 内部 SDK 测试版禁止事项

内部 SDK 测试版禁止以下事项：

- 商业化使用个人 SDK 权限。
- 向真实用户开放。
- 将个人自用权限包装为商业授权。
- 绕过 quote-service / adapter 直接让前端调用 SDK。
- 大规模抓取历史数据。
- 全市场订阅压测。
- 自动交易。

内部 SDK 测试版不得变相成为公开试用版的数据来源，也不得绕过服务端隔离边界向前端、小程序或 H5 暴露 SDK 能力。

## 10. Mock Provider 与真实 Provider 边界

当前阶段继续坚持 Mock First。Mock Provider 是公开试用版默认使用的数据来源，用于支持演示、体验、界面联调和退休进度计算。

真实 Provider 只允许在内部 SDK 测试版中用于受控验证。真实 Provider 的目标不是替代 Mock Provider 直接上线，而是帮助团队确认：

- 字段名称与字段含义能否对齐。
- 数值单位、时间戳和证券标识是否一致。
- 错误码和异常场景如何映射。
- quote-service 是否能统一屏蔽底层 SDK 差异。

公开试用版不得直接切换到真实 Provider。任何从 Mock Provider 迁移到真实 Provider 的动作，都必须在企业授权、数据协议、费用、白名单和使用范围确认后另行评审。

## 11. quote-service / yinhe adapter 边界

SDK 只允许通过服务端 quote-service / yinhe adapter 隔离。前端、小程序、H5 不得直接调用 SDK。

quote-service / yinhe adapter 的边界包括：

- 由服务端统一封装 SDK 调用。
- 由 adapter 负责字段映射、错误码转换和 Provider 差异处理。
- 由 quote-service 对上层提供最小、稳定、只读的行情接口。
- 由服务端控制权限、白名单、调用频率、日志和异常处理。

禁止让前端、小程序、H5 直接持有 SDK 权限、调用 SDK 方法或绕过 adapter 访问真实 Provider。

## 12. 商业授权边界

订阅额度不等于商业授权。个人 SDK 权限、测试权限、试用额度或内部订阅能力，都不能自动解释为可对外商业化使用的授权。

商业化前必须另行确认：

- 企业授权主体。
- 数据协议。
- 收费方式和费用标准。
- 可使用的数据范围。
- 可服务的用户范围。
- 可展示的数据类型。
- 可缓存、转发或二次加工的边界。
- IP、域名、AppID、小程序或服务端白名单。
- 监管、合规和审计要求。

在上述事项确认前，公开试用版不得使用个人 SDK 权限对外提供真实行情，也不得将内部 SDK 测试结果包装为商业产品能力。

## 13. 产品宣传边界

产品宣传必须与真实能力一致。当前阶段可以宣传的内容包括：

- 支持手动资产记录。
- 支持现金流退休率计算。
- 支持被动收入覆盖率展示。
- 支持退休进度展示。
- 使用 Mock 行情、演示数据、用户自填数据或延迟公开数据进行体验。

当前阶段禁止宣传：

- 已接入银河真实行情。
- 已提供银河真实实时行情。
- 已支持真实行情订阅。
- 已具备自动交易能力。
- 可输出投资建议或买卖建议。
- 可承诺收益或提高收益。
- 已取得商业行情授权，除非该授权已经另行完成书面确认。

所有对外文案都必须避免让用户误以为公开试用版已经完成真实 SDK 接入或具备真实行情商业服务能力。

## 14. 后续角色分工

后续工作建议按以下角色分工推进：

- 产品侧：维护公开试用版能力清单、禁止事项、页面文案和宣传口径。
- 技术侧：维护 Mock Provider、quote-service、yinhe adapter 和最小只读接口验证。
- SDK 验证侧：在本地受控环境中整理字段映射、错误码和接口行为。
- 商务与合规侧：确认企业授权、数据协议、费用、白名单和使用范围。
- 测试侧：分别验证公开试用版不触发真实 SDK，内部 SDK 测试版不向真实用户开放。

任何跨越公开试用版与内部 SDK 测试版边界的需求，都必须先更新本文档或形成单独评审记录。

## 15. 待确认问题

以下问题需要在商业化或真实 SDK 对外使用前确认：

- 是否已经取得企业级数据授权。
- 授权是否允许对外服务真实用户。
- 授权是否允许在小程序、H5 或其他前端场景展示。
- 授权是否允许缓存、转发、聚合或二次加工行情数据。
- 授权是否包含实时行情、延迟行情、历史行情和订阅行情的不同范围。
- quote-service 的白名单、频率限制和审计日志要求是什么。
- yinhe adapter 的字段映射和错误码是否已经完成内部验收。
- 公开试用版的所有页面是否已经清理真实行情误导性表达。
- 内部 SDK 测试版是否有明确访问控制，确保不会向真实用户开放。
- 商业化前是否已经完成费用、合同、数据协议和使用范围确认。
