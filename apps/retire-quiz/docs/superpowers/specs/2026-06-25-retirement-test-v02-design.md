# 《测一测你还有多久退休》V0.2 优化设计

## 目标

把当前 MVP 从“能算出退休进度”升级为“用户能看懂每个进度指标怎么计算，也愿意分享自己的自由进度卡”。

本轮不改变项目边界：

- 不修改《退了吗》/ `wealth-freedom-demo` 主项目。
- 不接入后端、数据库、登录系统、真实金融账户或外部 API。
- 不新增生产网络请求。
- 不上传用户数据。
- 不提供投资、理财、保险或退休决策建议。
- 继续使用 HTML、CSS、Vanilla JavaScript、Canvas、LocalStorage 和 Node 内置测试。

## 当前问题

当前版本已经能完成输入、测算、报告和海报，但 V0.2 需求指出几个表达层面的风险：

1. 用户不容易理解“目标资产进度”到底包含什么。
2. “房产净值”会诱导用户先扣房贷，再在负债页重复填写房贷，导致双重扣减。
3. “资产退休率 / 资产工作力 / 劳动依赖率”等词偏专业，不适合作为主结果展示。
4. 资产模型达标和现金流覆盖容易被混为一谈。
5. “已达到目标状态”“预计退休年龄”这类表达可能被理解成退休建议。
6. 分享海报缺少统一的“全民默认版自由进度卡”结构。
7. 海报“小结”必须根据不同用户结果动态变化。

## 设计原则

### 现金流退休率是第一核心指标

内部公式继续使用：

```text
现金流退休率 = 稳定月被动收入 / 目标月生活成本
```

用户侧包装为：

```text
自由进度
```

核心解释：

```text
它表示你的稳定被动收入，能覆盖多少目标生活成本。
它回答的是：我的生活有多少已经不靠工资？
```

### 目标资产进度是辅助指标

统一替换“资产退休率”主展示为：

```text
目标资产进度
```

副标题：

```text
净资产占目标资产
```

公式：

```text
目标资产进度 = 当前净资产 / 目标退休资产
当前净资产 = 总资产 - 总负债
目标退休资产 = 目标月生活成本 × 12 × 25
```

必须说明：

```text
目标资产进度高，不代表现金流已经覆盖生活。
真正衡量“不靠工资生活”的核心指标，仍然是现金流退休率。
```

### 房产口径改为房产估值

资产页使用：

```text
房产估值
```

字段说明：

```text
请填写房产当前大致市场估值，不要在这里扣除房贷。
剩余房贷请在负债页填写。
```

负债页使用：

```text
剩余房贷
```

字段说明：

```text
请填写当前仍未偿还的房贷本金余额。
```

计算口径：

```text
总资产 = 现金 + 基金 + 股票 + 黄金 + 房产估值 + 其他资产
总负债 = 剩余房贷 + 车贷 + 消费贷 + 其他负债
当前净资产 = 总资产 - 总负债
```

LocalStorage 兼容策略：

- 新字段名使用 `propertyValue`。
- 读取时兼容 `propertyEquity`、`propertyNetValue`、`realEstateNetValue`。
- 兼容只负责迁移草稿值，不改变净资产计算规则。

## 状态体系

新增三个派生状态：

```js
cashFlowStatus
assetStatus
overallStatus
```

### cashFlowStatus

按现金流退休率划分：

| 条件 | 标签 |
|---|---|
| `rate <= 0` | 完全劳动依赖期 |
| `0 < rate < 0.2` | 现金流萌芽期 |
| `0.2 <= rate < 0.5` | 资产开始工作期 |
| `0.5 <= rate < 0.8` | 半退休准备期 |
| `0.8 <= rate < 1` | 接近现金流覆盖期 |
| `rate >= 1` | 现金流覆盖观察期 |

### assetStatus

按目标资产进度划分：

| 条件 | 标签 |
|---|---|
| `progress < 0` | 资产负债修复期 |
| `0 <= progress < 0.2` | 资产积累起步期 |
| `0.2 <= progress < 0.5` | 资产积累推进期 |
| `0.5 <= progress < 0.8` | 资产接近目标期 |
| `0.8 <= progress < 1` | 资产临近达标期 |
| `progress >= 1` | 资产模型达标期 |

资产状态只说明资产目标完成情况，不代表现金流已经覆盖生活。

### overallStatus

综合判断优先看现金流：

- 净资产 < 0：当前优先级不是退休，而是修复资产负债表、建立安全垫、降低高息负债。
- 现金流退休率 >= 100%：从现金流角度看，稳定被动收入已经覆盖目标生活成本；但不代表可以立即辞职。
- 现金流退休率 < 100%，目标资产进度 >= 100%：资产模型达标，但现金流尚未完全覆盖生活成本，仍需工资或主动收入支持。
- 现金流退休率 < 100%，目标资产进度 >= 80%：资产基础较好，但现金流仍未完全覆盖生活成本。
- 现金流退休率 < 50%，目标资产进度 < 80%：仍处于资产积累与现金流建设阶段。

禁止输出：

- 可以退休
- 财务自由
- 已达到目标状态
- 资产已接管生活
- 稳赚
- 保证收益

## 结果页设计

结果页顶部新增结论卡片，优先解释用户最该看到的结论：

```text
你的自由进度为 40%。

当前稳定被动收入可以覆盖 40% 的目标生活成本。
这说明你的资产已经开始承担一部分生活压力，
但你仍有约 60% 的目标生活成本需要依赖工资或主动收入。

按资产模型观察，你已经接近目标；
但按现金流模型观察，你还没有真正实现现金流覆盖。
```

主指标名称调整为：

- 现金流退休率 / 自由进度
- 目标资产进度
- 资产月收入
- 工资依赖
- 安全垫月数

新增“这些指标怎么算？”可展开说明模块，解释：

- 现金流退休率
- 目标资产进度
- 当前净资产
- 资产月收入
- 工资依赖
- 年生活成本约 25 倍简化估算

弱化退休时间表达：

- 现金流覆盖时：显示“现金流已覆盖目标生活成本”，并保留风险提示。
- 资产模型达标但现金流未达标时：显示“资产模型：当前已达标；现金流模型：尚未达标”。
- 可估算时：显示“按当前输入，保守模型估算还需约 X 年达到目标资产。”
- 不可估算时：显示“当前月可投入金额不足，暂不估算具体达成时间。”

## 动态小结

新增函数：

```js
getPosterSummaryByCashFlowRate(rate, stablePassiveIncome, netAssets)
```

返回：

```js
{
  stageLabel: string,
  summaryText: string
}
```

规则：

| 条件 | stageLabel | summaryText |
|---|---|---|
| `netAssets < 0` | 资产负债修复中 | 当前优先级不是退休，而是先修复资产负债表。 |
| `stablePassiveIncome <= 0` | 打基础中 | 稳定现金流还没真正接班，现在主要还是靠自己扛。 |
| `0 < rate < 0.1` | 现金流萌芽中 | 资产刚刚开始发力，但生活大部分还要靠工资支撑。 |
| `0.1 <= rate < 0.3` | 资产开始打工中 | 资产已经开始上班，但主力员工还是我自己。 |
| `0.3 <= rate < 0.6` | 自由感变具体了 | 资产已经能分担一部分生活成本，你的选择权正在慢慢变多。 |
| `0.6 <= rate < 0.9` | 资产成为重要帮手 | 资产已经承担了不少生活压力，但还没有完全替代工资。 |
| `0.9 <= rate < 1` | 接近现金流覆盖 | 距离覆盖目标生活成本已经不远，下一步更要看稳定性和安全垫。 |
| `rate >= 1` | 现金流覆盖观察期 | 从现金流看，生活成本已被覆盖，但仍要看稳定性、安全垫和长期风险。 |

## 分享海报设计

分享海报定位为：

```text
全民默认版自由进度卡
```

内容结构：

1. 顶部品牌区：`测一测你的自由进度｜退了吗`
2. 主标题：`我的自由进度`
3. 最大视觉数字：如 `40%`
4. 解释句：`现在有 40% 的生活成本，不用完全靠工资来扛。`
5. 动态阶段标签
6. 三个指标卡片：
   - 目标资产进度 / 净资产占目标资产
   - 资产月收入 / 每月被动 + 半被动收入
   - 工资依赖 / 仍需工资覆盖生活成本
7. 动态小结
8. 底部金句：`不是想躺平，只是想多一点选择生活的权利。`
9. 合规提示
10. 无真实链接时不生成二维码，只保留轻 CTA 文案：`你也可以测测自己的自由进度`

视觉方向：

- 奶油白 / 暖灰白背景
- 低饱和豆沙粉、奶咖色、暖灰色
- 中性、高级、克制、生活化
- 圆形进度环作为主视觉
- 三张指标卡片
- 浅阴影和柔和光影
- 不使用具体人物
- 不使用复杂插画
- 不使用贴纸堆砌
- 不金融机构报告化
- 不依赖外部字体或图片
