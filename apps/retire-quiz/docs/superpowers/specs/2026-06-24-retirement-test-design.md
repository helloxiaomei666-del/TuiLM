# 《测一测你还有多久退休》MVP 设计规格

## 1. 目标与成功标准

在 `C:\Users\18955\Desktop\Codex_work\ios_app\retirement-test` 创建一个与《退了吗》完全隔离的纯前端 MVP。用户应能在 3 分钟内完成 5 步输入，获得简洁、可截图、可生成图片的退休进度报告，并看到进入《退了吗》的占位入口。

成功标准：

- 页面无需后端即可运行，不发起任何网络请求。
- 首页、5 步输入、报告、分享海报形成完整路径。
- 核心公式、边界条件和退休时间估算有自动化测试。
- 报告明确区分资产、稳定被动收入、半被动收入和主动劳动收入。
- 全程不推荐金融产品，不承诺收益，不提供投资或退休决策建议。
- 不修改、移动、删除或重命名 `wealth-freedom-demo` 及其他现有文件。

## 2. 产品边界

本产品是一次性财务状态测算和传播工具，不是资产管理、记账、理财、退休规划、投资建议或金融产品推荐工具。它负责获客、测试、传播和分享；《退了吗》负责长期记录、跟踪和留存。

MVP 不包含账号、支付、后端、云同步、行情、平台分享 SDK、官方养老金待遇测算或与原项目的代码耦合。报告 CTA 仅为占位按钮，不跳转真实地址。

核心表达：

> 真正的退休能力，不只是你有多少资产，而是你的资产每个月能替你承担多少生活成本。

## 3. 技术架构与文件职责

采用零依赖的 HTML、CSS 和 JavaScript。浏览器脚本使用经典脚本加载，使用户直接双击 `index.html` 时也能运行；计算模块同时暴露浏览器全局对象和 CommonJS 导出，以便使用 Node.js 内置测试运行器测试，不引入 npm 依赖。

计划文件：

- `index.html`：首页、5 步表单、报告、免责声明和分享卡片容器。
- `styles.css`：移动端优先的布局、组件、状态和打印/截图样式。
- `js/calculator.js`：输入标准化、周期折算、指标、退休时间和推进器计算。
- `js/app.js`：步骤导航、验证、LocalStorage 草稿、报告渲染和 CTA 行为。
- `js/share-card.js`：Canvas 海报绘制、预览和 PNG 保存。
- `tests/calculator.test.js`：计算公式和边界条件测试。
- `README.md`：本地运行、测试、范围、隐私和项目隔离说明。
- `docs/product-notes.md`：产品定位、指标口径、简化假设、免责声明和后续接入边界。

所有新增内容只存在于 `retirement-test` 目录。项目自身拥有独立 Git 仓库。

## 4. 用户路径与交互

### 4.1 首页

首屏显示：

- 标题：《测一测你还有多久退休》
- 副标题：3分钟生成你的退休进度报告
- 价值主张：测一测，你的资产已经替你承担了多少生活？
- 主按钮：开始测试
- 辅助说明：数据仅保存在当前浏览器，不上传服务器。

### 4.2 五步输入

页面一次只显示一步，通过顶部细进度条和“第 N/5 步”建立进度感。每步提供“上一步”和“继续”，第 5 步使用“生成报告”。刷新后从 LocalStorage 恢复草稿；“清空数据”必须经过页面内确认后清除草稿并回到首页。

步骤与字段：

1. 基础信息：年龄、城市、希望退休年龄、当前月生活成本、理想退休后月生活成本。理想成本留空时继承当前生活成本。
2. 资产：现金、基金、股票、黄金、房产净值、其他资产，并实时显示总资产。
3. 负债：房贷、车贷、消费贷、其他负债，并实时显示总负债和净资产。
4. 主动现金流：月工资、月副业、月生活支出、月固定支出、月还贷支出，并显示保守月可投入金额。
5. 被动与半被动收入：股息、房租、利息、REITs、已领取养老金、已领取年金、版权、其他稳定现金流、半被动收入。每项选择月、季、年或不固定。

“不固定”金额不计入稳定月被动收入。半被动收入无论选择何种稳定周期，都只计入资产工作力，不计入现金流退休率，并在报告中单独标注其维护属性。

### 4.3 报告

报告按照以下顺序呈现：

1. 现金流退休率：主视觉大数字、进度条、状态分级和覆盖解释。
2. 资产退休率：目标完成度及“现金流更关键”提示。
3. 资产工作力：稳定被动收入与半被动收入分开展示。
4. 劳动依赖率：现实解释，不使用焦虑文案。
5. 安全垫月数：仅基于现金和当前月生活成本。
6. 预计退休年龄：零收益保守模型及不可估算状态。
7. 退休倒计时：以“距离目标状态”表述，避免承诺。
8. 退休推进器：新增 100、500、1000 元月被动收入的场景结果。
9. 完整免责声明。
10. 生成分享海报、重新测算和《退了吗》占位 CTA。

## 5. 计算模型

所有金额先通过 `toAmount` 标准化：空值、非数字、负数金额均按 0 处理。净资产允许为负数，因为它由非负资产减去非负负债得到。

### 5.1 基础指标

```text
总资产 = 现金 + 基金 + 股票 + 黄金 + 房产净值 + 其他资产
总负债 = 房贷 + 车贷 + 消费贷 + 其他负债
净资产 = 总资产 - 总负债
目标月生活成本 = 理想退休后月生活成本；留空时取当前月生活成本
退休目标资产 = 目标月生活成本 × 12 ÷ 4%
资产退休率 = 净资产 ÷ 退休目标资产
```

周期折算：月金额保持不变，季金额除以 3，年金额除以 12，不固定金额折算为 0。

```text
月稳定被动收入 = 股息 + 房租 + 利息 + REITs + 已领取养老金
                  + 已领取年金 + 版权收入 + 其他稳定现金流
现金流退休率 = 月稳定被动收入 ÷ 目标月生活成本
劳动依赖率原值 = 1 - 现金流退休率
劳动依赖率展示值 = max(0, 劳动依赖率原值)
月半被动收入 = 半被动收入按稳定周期折算；不固定时为 0
资产工作力 = 月稳定被动收入 + 月半被动收入
安全垫月数 = 现金 ÷ 当前月生活成本
```

百分比最多保留 1 位小数，人民币使用 `Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' })`。比率不强制截断到 100%，以便报告显示真实超额覆盖；进度条视觉宽度最多为 100%。

### 5.2 状态分级

- 现金流退休率 `< 10%`：生存依赖期——基本靠工资活着。
- `10% ≤ 比率 < 30%`：现金流萌芽期——资产开始承担一小部分生活。
- `30% ≤ 比率 < 60%`：半自由期——已经具备一定选择权。
- `60% ≤ 比率 < 90%`：准退休期——工资不再是唯一支柱。
- `比率 ≥ 90%`：现金流退休期——基本具备退休现金流基础。

达到 90% 或 100% 不表示可以辞职。现金流退休率超过 100% 时显示“当前稳定被动收入已覆盖目标生活成本”；资产退休率超过 100% 时显示“目标资产已达成”，同时继续提示现金流覆盖情况。

### 5.3 预计退休时间

采用用户确认的零收益保守模型，不假设投资回报、通胀或收入增长。

```text
月主动收入 = 月工资 + 月副业
月主动支出 = 月生活支出 + 月固定支出 + 月还贷支出
月可投入金额 = max(0, 月主动收入 - 月主动支出)
剩余目标月成本 = max(0, 目标月生活成本 - 月稳定被动收入)
现金流调整后目标资产 = 剩余目标月成本 × 12 ÷ 4%
待积累缺口 = max(0, 现金流调整后目标资产 - 净资产)
预计所需月数 = 待积累缺口 ÷ 月可投入金额
预计退休年龄 = 当前年龄 + 预计所需月数 ÷ 12
退休倒计时天数 = round(预计所需月数 × 365.2425 ÷ 12)
```

若缺口为 0，则预计所需月数和倒计时为 0，预计退休年龄为当前年龄。若缺口大于 0 且月可投入金额为 0，则结果为“按当前输入暂无法估算”，不返回 `Infinity`、`NaN` 或虚假年龄。希望退休年龄只用于报告比较“预计比希望早/晚多少年”，不改变模型结果。

### 5.4 退休推进器

分别把 100、500、1000 元加入月稳定被动收入，重新计算现金流调整后目标资产和预计所需月数：

```text
预计提前月数 = max(0, 基准预计月数 - 场景预计月数)
预计提前年数 = 预计提前月数 ÷ 12
```

基准时间不可估算时，推进器显示“当前可投入金额不足，暂无法比较”；基准缺口已经为 0 时显示“当前已达到模型目标”。场景只表示数学模拟，不说明如何获得新增收入，也不推荐任何资产或产品。

## 6. 验证与错误处理

生成报告前必须满足：年龄大于 0、当前月生活成本大于 0、目标月生活成本大于 0。希望退休年龄若填写，必须不小于当前年龄。其他空字段按 0 处理。

错误以字段旁短文案展示，并将焦点移动到第一个错误字段，不使用浏览器弹窗。除数为 0 时相应指标返回不可用状态，由界面显示“暂无法计算”。所有输入和 LocalStorage 恢复数据再次经过标准化，防止 `NaN` 和异常字符串进入报告。

LocalStorage 只保存在当前浏览器。页面明确说明数据不会上传，并提供清除入口。项目不加载第三方字体、脚本、图片或分析工具。

## 7. 分享海报

点击“生成分享海报”后，在 Canvas 绘制适合手机保存的长图，包含：现金流退休率、资产退休率、资产工作力、劳动依赖率、预计退休年龄、距离目标状态天数、状态分级，以及“退休不是年龄，是资产开始承担生活。”

海报底部显示“基于个人输入和简化假设，仅供自我观察，不构成任何建议”。提供预览和“保存 PNG”按钮。MVP 不调用微信、微博、小红书或其他平台 SDK。

## 8. 视觉设计

移动端优先，白底、黑字、灰色层级和单一冷蓝强调色。使用系统字体，避免外部资源。主结果使用大字号，卡片以细边框和留白区分，不使用红绿涨跌、K 线、收益率刺激或金融终端视觉。

桌面端内容最大宽度约 720 像素，保持手机报告的截图感。触控目标不小于 44 像素；表单标签始终可见；键盘类型按年龄和金额选择数字输入；动态结果区域使用适当的可访问状态提示。

## 9. 免责声明

页面和产品说明必须完整展示：

> 本工具仅用于个人财务状态测算和自我观察。结果基于用户输入和简化假设生成。不构成投资建议、理财建议、保险建议或退休决策建议。不推荐任何金融产品，不承诺任何收益，不预测市场走势，不建议用户买入、卖出或持有任何资产。

同时说明：4% 仅为简化估算假设，不代表确定收益率或未来可实现收益；被动收入真实性和持续性不由系统验证；半被动收入仍需维护；养老金、公积金、企业年金和职业年金仅按用户输入展示，不代表官方待遇测算，未开始领取的保障账户不计入当前被动收入。

## 10. 测试与验收

自动化测试覆盖：

- 金额标准化和月/季/年/不固定周期折算。
- 标准案例的总资产、总负债、净资产和五项报告指标。
- 目标成本为 0 时的安全返回。
- 负债大于资产时的负净资产。
- 现金流退休率及资产退休率超过 100%。
- 半被动收入不进入现金流退休率。
- 零收益退休时间、目标已达成和无法估算三种状态。
- 100、500、1000 元推进器场景。

浏览器验收覆盖：

- 首页至 5 步表单至报告的完整路径。
- 前进、后退、字段校验、刷新恢复和清空草稿。
- 移动端与桌面端布局，无横向溢出。
- 报告指标、状态文案、免责声明和 CTA 完整。
- Canvas 海报生成、预览和 PNG 保存动作可用。
- 页面无控制台错误、无网络请求。
- 通过文件清单和 Git 状态确认 `wealth-freedom-demo` 没有发生变化。

## 11. 后续接入边界

MVP 的《退了吗》CTA 使用无真实跳转的占位行为。未来接入仅替换 CTA 目标或增加用户主动触发的数据导出映射；不得直接依赖、复制或修改原项目代码。任何真实数据传递都需要另行设计用户同意、字段最小化和隐私提示。

## 5. 计算模型

所有金额先通过 `toAmount` 标准化：空值、非数字、负数金额均按 0 处理。净资产允许为负数，因为它由非负资产减去非负负债得到。

### 5.1 基础指标

```text
总资产 = 现金 + 基金 + 股票 + 黄金 + 房产净值 + 其他资产
总负债 = 房贷 + 车贷 + 消费贷 + 其他负债
净资产 = 总资产 - 总负债
目标月生活成本 = 理想退休后月生活成本；留空时取当前月生活成本
退休目标资产 = 目标月生活成本 × 12 ÷ 4%
资产退休率 = 净资产 ÷ 退休目标资产
```

周期折算：月金额保持不变，季金额除以 3，年金额除以 12，不固定金额折算为 0。

```text
月稳定被动收入 = 股息 + 房租 + 利息 + REITs + 已领取养老金
                  + 已领取年金 + 版权收入 + 其他稳定现金流
现金流退休率 = 月稳定被动收入 ÷ 目标月生活成本
劳动依赖率原值 = 1 - 现金流退休率
劳动依赖率展示值 = max(0, 劳动依赖率原值)
月半被动收入 = 半被动收入按稳定周期折算；不固定时为 0
资产工作力 = 月稳定被动收入 + 月半被动收入
安全垫月数 = 现金 ÷ 当前月生活成本
```

百分比最多保留 1 位小数，人民币使用 `Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' })`。比率不强制截断到 100%，进度条视觉宽度最多为 100%。

### 5.2 状态分级

- 现金流退休率 `< 10%`：生存依赖期——基本靠工资活着。
- `10% ≤ 比率 < 30%`：现金流萌芽期——资产开始承担一小部分生活。
- `30% ≤ 比率 < 60%`：半自由期——已经具备一定选择权。
- `60% ≤ 比率 < 90%`：准退休期——工资不再是唯一支柱。
- `比率 ≥ 90%`：现金流退休期——基本具备退休现金流基础。

达到 90% 或 100% 不表示可以辞职。现金流退休率超过 100% 时显示“当前稳定被动收入已覆盖目标生活成本”；资产退休率超过 100% 时显示“目标资产已达成”，同时继续提示现金流覆盖情况。

### 5.3 预计退休时间

采用用户确认的零收益保守模型，不假设投资回报、通胀或收入增长。

```text
月主动收入 = 月工资 + 月副业
月主动支出 = 月生活支出 + 月固定支出 + 月还贷支出
月可投入金额 = max(0, 月主动收入 - 月主动支出)
剩余目标月成本 = max(0, 目标月生活成本 - 月稳定被动收入)
现金流调整后目标资产 = 剩余目标月成本 × 12 ÷ 4%
待积累缺口 = max(0, 现金流调整后目标资产 - 净资产)
预计所需月数 = 待积累缺口 ÷ 月可投入金额
预计退休年龄 = 当前年龄 + 预计所需月数 ÷ 12
退休倒计时天数 = round(预计所需月数 × 365.2425 ÷ 12)
```

若缺口为 0，则预计所需月数和倒计时为 0，预计退休年龄为当前年龄。若缺口大于 0 且月可投入金额为 0，则结果为“按当前输入暂无法估算”，不返回 `Infinity`、`NaN` 或虚假年龄。希望退休年龄只用于报告比较“预计比希望早/晚多少年”，不改变模型结果。

### 5.4 退休推进器

分别把 100、500、1000 元加入月稳定被动收入，重新计算现金流调整后目标资产和预计所需月数：

```text
预计提前月数 = max(0, 基准预计月数 - 场景预计月数)
预计提前年数 = 预计提前月数 ÷ 12
```

基准时间不可估算时显示“当前可投入金额不足，暂无法比较”；基准缺口已经为 0 时显示“当前已达到模型目标”。场景只表示数学模拟，不说明如何获得新增收入，也不推荐任何资产或产品。

## 6. 验证与错误处理

生成报告前必须满足：年龄大于 0、当前月生活成本大于 0、目标月生活成本大于 0。希望退休年龄若填写，必须不小于当前年龄。其他空字段按 0 处理。

错误以字段旁短文案展示，并将焦点移动到第一个错误字段，不使用浏览器弹窗。除数为 0 时相应指标返回不可用状态，由界面显示“暂无法计算”。所有输入和 LocalStorage 恢复数据再次经过标准化，防止 `NaN` 和异常字符串进入报告。

LocalStorage 只保存在当前浏览器。页面明确说明数据不会上传，并提供清除入口。项目不加载第三方字体、脚本、图片或分析工具。

桌面端内容最大宽度约 720 像素。触控目标不小于 44 像素；表单标签始终可见；年龄和金额采用合适的数字键盘；动态结果区域提供可访问状态提示。
