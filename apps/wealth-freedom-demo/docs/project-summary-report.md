# 「退了吗」项目总结报告

日期：2026-06-14

## 1. 项目简介

「退了吗」是一款面向个人用户的财富记录与退休进度测算工具。产品围绕一个简单问题展开：

> 今天，你退休了吗？

用户录入收入、支出、资产、保障账户和固定拖累项后，系统会计算当前退休进度、预计达成时间、目标缺口、每月可投入金额，并展示资产变化对退休进度的影响。

产品定位不是投资顾问，也不是交易工具。项目坚持以下边界：

- 不做买入、卖出、加仓、减仓建议。
- 不推荐股票、基金、债券、黄金或其他金融产品。
- 不承诺收益。
- 不提供自动交易能力。
- 不要求用户提供交易密码、支付密码或第三方平台登录信息。
- 只做资产记录、估值更新、退休进度测算和解释。

## 2. 用户痛点

当前个人财富管理存在几个明显问题：

1. 资产分散在银行卡、基金账户、券商账户、黄金账户、公积金、养老金等多个地方，普通用户缺少统一视角。
2. 很多人知道自己有多少钱，但不知道这些钱对应的退休进度。
3. 传统理财工具偏交易和产品推荐，容易制造焦虑，也容易让用户产生不信任。
4. 用户真正需要的是一个长期、克制、可解释的个人财富仪表盘。
5. 对年轻上班族来说，“几岁能退休”“每月多存多少钱会提前多久”是一个高兴趣、低门槛、容易传播的问题。

## 3. 目标用户

第一阶段建议聚焦以下用户：

- 25-40 岁城市上班族。
- 有工资收入，并开始关注长期储蓄、投资和退休规划。
- 拥有基金、ETF、股票、黄金、公积金、养老金等多类资产。
- 不一定是高净值用户，但有记录资产和测算未来的需求。
- 对荐股、荐基、收益承诺较敏感，更愿意接受中立工具。

## 4. 当前项目进度

项目目前已经从网页原型推进到微信小程序 MVP 与估值后端架构阶段。

### 4.1 Web Demo

当前 Web Demo 已具备：

- 退休进度测算。
- 当前可投资资产统计。
- 每月可投入金额计算。
- 工资增长率与投资回测收益率测算。
- 未来资产路线图。
- 现金、基金/股票、债券、商品四类资产录入。
- 保障账户录入，包括养老金、公积金、补充公积金、企业年金、职业年金。
- 拖累项录入，包括房贷、车贷、医疗、其他固定支出。
- 本地数据保存与清除。
- Mock 行情刷新。
- OCR 截图导入模拟流程，且要求用户确认后才回填。

### 4.2 微信小程序 MVP

当前已建立微信小程序工程，包含 5 个主要 tab：

- 总览：展示退休进度、预计退休时间、可投资资产、每月可投入、保障账户、最近估值。
- 资产：支持添加、删除资产，支持 mock 估值刷新与 OCR 模拟确认流程。
- 保障：录入养老金、公积金、补充公积金、企业年金、职业年金。
- 路线：展示未来资产路线、年度节点、目标差额。
- 拖累项：记录影响退休进度的固定支出，并参与测算。

小程序还包含隐私与免责声明页面，用于说明本地存储、OCR 确认流程和非投资建议边界。

### 4.3 估值后端架构

项目已建立 `quote-service` 后端骨架，用于未来接入真实行情和估值服务。当前能力包括：

- 单条 quote 查询。
- 批量 quote 查询。
- 估值预览。
- 每日估值快照。
- 本地 mock provider。
- Tushare provider 骨架。
- 恒生 LIGHT 云 provider 适配准备。
- provider 权限不足、认证失败、空数据等错误兜底。
- 后端环境变量读取 API key，避免把密钥写入小程序前端。

当前默认仍使用 mock/local 估值，不直接请求真实第三方 API。真实接口接入前，需要确认商用展示、缓存、调用频率和数据来源标注要求。

截至 2026-06-14，项目自动化验证情况：

- `node scripts/validate-miniapp.js`：小程序结构校验通过。

测试覆盖内容包括：

- 投资回测收益率。
- 保障账户不计入可投资资产。
- 拖累项非整百金额。

- 小程序五个 tab 页面级冒烟流程。
- quote client 与 quote-service。
- provider 错误兜底。
- 不泄露 API key/token 的静态检查。

## 5. 商业价值判断

本项目的商业价值不在于替用户做投资决策，而在于帮助用户建立长期财富视角。

核心商业价值包括：

1. **强问题钩子**
   “我几岁能退休”是一个天然有传播性的消费级问题。

2. **低门槛使用**
   用户不需要学习复杂理财知识，只要输入资产、收入和支出，就能得到结果。

3. **适合付费报告**
   用户完成测算后，对完整报告、拖累项分析、提前退休模拟、年度复盘有明确付费场景。

4. **合规边界相对清晰**
   项目不做交易、不推荐产品、不承诺收益，降低了金融产品化风险。

5. **可持续复访**
   用户资产、工资、支出每月都会变化，产品可以逐步发展为个人退休进度仪表盘。

6. **微信生态适配**
   小程序适合轻量访问、分享传播和微信支付，适合早期商业验证。

## 6. 初步商业模式

第一阶段建议采用“免费测算 + 付费报告”的方式，而不是一开始做会员订阅。

### 免费能力

- 基础退休进度测算。
- 预计退休时间。
- 可投资资产与每月可投入。
- 基础路线图。

### 付费能力

可测试以下付费项：

- 完整退休分析报告。
- 拖累项分析。
- 如果每月多存 1000、3000、5000 元，退休时间如何变化。
- 年度财富复盘。
- 家庭资产版。
- PDF 或长图报告导出。
- 更多 OCR 识别额度。

建议早期价格：

- 单次报告：9.9 元、19.9 元、29.9 元。
- 年度复盘：39 元、59 元、99 元。
- 后续会员：99-199 元/年。

## 7. 当前尚未完成的关键工作

项目要从 MVP 走向可上线、可收费版本，还需要完成以下工作：

### 7.1 小程序真实环境验收

- 配置真实小程序 AppID。
- 导入微信开发者工具。
- 完成模拟器和真机预览。
- 检查五个 tab 页面是否稳定。
- 检查页面是否存在文字重叠、按钮遮挡、横向溢出等问题。

### 7.2 真实估值接口接入

当前正在推进恒生相关真实估值接口申请。后续需要：

- 确认商用展示授权。
- 确认缓存规则。
- 确认调用频率。
- 确认必须展示的数据来源文案。
- 将真实 provider 接入后端 `quote-service`。
- 小程序只请求自有后端，不保存第三方密钥。
- 接入后补充 fixture 测试和错误兜底测试。

### 7.3 云端账号与数据存储

当前小程序仍使用本地存储。正式上线前需要：

- 微信登录。
- 用户数据云端保存。
- 资产、拖累项、保障账户、估值快照按用户隔离。
- 数据删除。
- 账号注销。
- 必要的数据导出说明。

### 7.4 付费报告闭环

商业验证必须补齐：

- 微信支付。
- 免费基础测算。
- 付费完整报告。
- 订单记录。
- 支付状态校验。
- 退款处理。
- 报告分享图。
- 访问、测算、支付、复访转化统计。

### 7.5 正式合规材料

需要将当前草案升级为正式文本：

- 隐私政策。
- 用户协议。
- 免责声明。
- 数据处理说明。
- 行情来源说明。
- 非投资建议说明。

上线前建议由专业人士复核。

## 9. 融资用途建议

如果获得天使资金，资金应优先用于验证商业闭环，而不是盲目扩大团队。

建议用途：

- 产品开发：小程序上线、支付、报告、后台。
- 后端能力：云存储、估值快照、报告服务、安全基础设施。
- 数据与合规：真实接口授权、法律文本复核、隐私和免责声明。
- 增长测试：内容投放、素材制作、渠道测试。
- 创始人基本生活费：保证 6-12 个月持续打磨。

不建议早期大量投入：

- 完整 iOS App。
- 大规模团队。
- 办公室。
- 昂贵金融终端数据。
- 自动交易或投顾功能。
- 金融产品推荐。

## 10. 主要风险

### 10.1 用户录入门槛

用户需要输入资产、收入和支出。若流程过长，完成率可能偏低。需要控制首次测算在 3-5 分钟内完成。

### 10.2 真实数据授权

行情和估值数据涉及授权、展示、缓存和调用频率限制。正式商业化前必须确认供应商条款。

### 10.3 合规表达

产品不能被用户或平台理解为投资建议工具。所有文案必须保持“记录、测算、解释”的边界。

### 10.4 付费意愿

用户对单次报告是否愿意付费，需要通过真实支付测试验证。

### 10.5 获客成本

项目能否成为小生意，关键取决于内容获客成本是否低于报告收入。

## 11. 阶段性结论

「退了吗」目前已经具备较完整的 MVP 基础：前端体验、小程序工程、计算核心、资产估值后端架构、合规边界和自动测试都已初步成型。

项目现阶段的核心任务不是继续堆功能，而是完成三个商业验证关键点：

1. 真实小程序体验版。
2. 合规真实估值接口。
3. 付费报告闭环。

如果这三件事跑通，项目有机会先发展为一个月收入几千到几万元的工具型小产品。后续如果能证明用户持续回来更新资产，并愿意为报告、复盘、家庭版和高级功能付费，项目才具备进一步融资和提高估值的基础。

当前最适合对外表达为：

> 「退了吗」是一个克制、中立、可解释的个人退休进度仪表盘，帮助用户看清资产、现金流和退休目标之间的距离。它不做投资建议，而是做长期财富记录和退休进度测算。
